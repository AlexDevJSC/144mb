MOUTH LAN 0.4.0 / WIRE M144/1 — 21-10-2026
Todos los campos multi-byte little endian. Datagramas UDP IPv4.

HEADER 12 B:
 magic ASCII M144 [4] + wire_version u8=1 + type u8 +
 length u16 + session u32.
TYPE 1 HELLO 36 B (session=0):
 world_id u64, seed u64, generator_version u32, nonce u32.
TYPE 2 WELCOME 36 B:
 remote_actor_id u64, remote_owner u32, echoed_nonce u32, tick u64.
TYPE 3 INPUT 22 B:
 seq u32, forward i8, strafe i8, yaw_mrad i16, sprint u8, jump u8.
 No issuer, actor_id or damage fields from client.
TYPE 4 SNAPSHOT 77 B (dos actores):
 tick u64, actor_count u8=2; por actor:
 actor_id u64, owner u32, x_mm/y_mm/z_mm/yaw_mrad i32.
TYPE 5 REJECT 13 B:
 code u8 1 (mundo/semilla/generador incompatible),
 code u8 2 (versión de wire HELLO incompatible).
TYPE 6 LEAVE 12 B:
 header con session válida, mejor esfuerzo, sin confirmación.

Trafico nominal aplicación:
 cliente INPUT 22*60=1320 B/s; host SNAP 77*20=1540 B/s.
 Total aprox 2860 B/s (sin header IP/UDP ni negociación).
 Client HELLO cada 500 ms, timeout 5000 ms sin bienvenida.
 Host filtra endpoint/session/seq crecientes y sólo envía al actor
 owner/ID validado de Bones. Cliente rechaza snapshots no crecientes
 o incompletos. LEAVE remoto termina sesión; corte abrupto produce
 reconexión temporal y estado LOST si falla dentro de la ventana.
 No hay autenticación fuerte: sólo LAN privada de confianza.

World_id, seed, generator_version deben coincidir en ambos extremos
ANTES del HELLO. No hay descubrimiento automático por IP, ni hashes de
biblioteca Eye/recetas, ni checkpoint de partida Skin/Brain.
No transmitir texturas, PNG ni píxeles continuamente.
No NAT/WAN, migración host, eventos persistentes fiables ni 4 jugadores.
